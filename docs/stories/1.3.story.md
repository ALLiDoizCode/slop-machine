### RFC Style Guidelines (RFC 7322)
[Source: Story 1.2 Dev Notes]

**Abstract Format:**
- 100-200 words
- No citations or references
- Self-contained summary of document

**Introduction Requirements:**
- Should include motivation for the work
- Should summarize background/context
- Should describe document structure
- Related work typically in Introduction or separate section

**Writing Style:**
- Technical but accessible
- No code in Introduction (save for specification sections)
- URLs should be in References, not running text
- RFC 2119 keywords in uppercase

### Related Work Context

**Lightning Network** [LIGHTNING]:
- Bitcoin payment channels with multi-hop routing
- Strengths: Large network, mature implementation
- Limitations: Bitcoin-only, routing complexity, channel liquidity requirements

**Raiden Network** [RAIDEN]:
- Ethereum state channels with off-chain transfers
- Strengths: Ethereum ecosystem, state channels
- Limitations: Complex setup, limited adoption, multi-hop complexity

**ILP/STREAM**:
- Interledger Protocol with streaming payments
- Strengths: Ledger-agnostic vision, streaming model
- Limitations: Complex architecture (100+ RFCs), abstract design

### Technical Constraints

**RFC 2119 Keywords:**
The RFC must use standardized requirement keywords:
- MUST, MUST NOT, SHALL, SHALL NOT - Absolute requirement
- SHOULD, SHOULD NOT - Recommendation
- MAY - Optional

**Citation Format:**
- Normative: [RFCXXXX] Author, "Title", RFC XXXX, Month Year
- Informative: Same format but in informative section
